# Кодстайл

Правила обязательны для `lib/`, `labs/` и `packages/`. Проверяются на ревью; то, что можно
проверить автоматически, включено в `analysis_options.yaml` и CI.

## Функции

- Одна функция — одна задача. Если тело не читается без комментария, оно делится.
- **Один `return` на функцию.** Вместо ранних выходов — `if`/`switch`-выражения или
  вынесенный предикат.
- **Вложенность не больше 4 уровней** (считая тело функции первым уровнем).
- Параметров больше четырёх — собираем в объект-аргумент.
- Логика проверок выносится в предикат с говорящим именем: `_canSubmit(state)` вместо
  условия на пять строк внутри `build`.

## Виджеты

- `build` не содержит бизнес-логики и условий глубже тернарника: каждой ветке — свой
  маленький `StatelessWidget`.
- Один файл — один публичный виджет плюс приватные части этого виджета.
- Список, карточка, бейдж, баннер — отдельные виджеты, а не вложенные `Row`/`Column`.

## Состояние и данные

- Слой `domain` без Flutter: там, где нужен `try/catch`, возвращаем `Result`.
- Репозиторий не бросает исключения наружу: ошибка превращается в `Failure` на границе.
- Потоки и подписки закрываются в `close()`/`dispose()`; контроллер закрывается в `onCancel`.

## Именование

- Булевы значения — `is/has/can/should`: `isOnline`, `hasPendingUpdate`, `canRetry`.
- Никаких сокращений, кроме общепринятых (`id`, `url`, `api`).
- Файлы — `snake_case.dart`, классы — `UpperCamelCase`, приватные члены — `_camelCase`.

## Что проверяет CI

| Проверка | Инструмент |
|---|---|
| ошибки и предупреждения анализатора | `flutter analyze`, `dart analyze` в пакетах |
| единый стиль форматирования | `dart format --set-exit-if-changed` |
| поведение | `flutter test` (приложение и каждая лаборатория) |
| компиляция Cloud Functions | `npm run build` |

Глубину вложенности и число `return` анализатор не проверяет — это правило ревью,
поэтому оно зафиксировано здесь и применяется при правках.
